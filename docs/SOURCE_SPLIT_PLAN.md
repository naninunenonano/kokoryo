## 調査結果と方式

本体は index.html の単一script。主な処理は1つのIIFE内にあり、末尾の既存イベントハンドラはIIFE外にある。
505個の関数宣言と多数の状態変数が相互参照し、オンライン適用には動的evalもある。
関数宣言の巻き上げに加えて、const/letの初期化、windowへのパック登録、イベントとタイマーの登録順序に依存する。
単純に複数のscriptタグへ移すと、共有スコープ・TDZ・公開グローバル・同名qの扱いが変わる。

このため編集ソースを機能別に分け、配信用JSをビルド時に元の順序へ戻す。
ES Modules、export/global化、ランタイムevalローダー、共通効果設計への書き換えは行わない。
index.htmlはHTML/CSSを維持し、元のscript位置でjs/app.jsをclassic scriptとして読む。
src/order.jsonが元の断片順序とクロージャ境界を保持する。bundleの手修正は禁止する。

## 編集先

- src/game.js: 進行、共通状態、資源・ダイス・命令書、設置確定、勝利・終了、持ち時間。
- src/card_effects.js: カード固有効果と関連する選択処理。関数本体ごと移す。
- src/characters.js: 領主・雇用データと能力、雇用・解雇・融合・コピー。
- src/decks.js: カードデータ、デッキ、山札・公開場、パック・ルール登録/API。
- src/ui.js: 描画、カード詳細、選択UI、ダイアログ表示。
- src/bot.js: Botの判断・進行・待機。判断基準は変更しない。
- src/online.js: Realtime、ルーム、同期、オンライン用の持ち時間確定処理。
- src/debug.js: 既存デバッグ・診断・プレイログ。追加機能は入れない。
- src/bootstrap.js: 既存の起動呼び出し・イベント/タイマー登録・末尾ハンドラ。

処理と表示が混在する既存関数は内部を細分化せず、そのまま担当ファイルへ置く。
本体JSの実行順は SDK → pack1.js → pack2.js → rules_pack1.js → js/app.js。
存在する追加パックは2本とルールJS1本。pack3.jsは未存在のため新設しない。

## 段階的な反映と検証

1. 本計画を開発ブランチへ記録（ゲームの変更なし）。
2. 分割・ビルド・依存台帳・回帰検査をコミットしPRを作成。
3. 別TESTリポジトリのPRで分割形式のプレビュー対応・対象PR固定を行う。
4. TESTのみ公開。main、公開ブランチ、Pages設定、本番Supabaseは変更しない。

分割前のHTML/JSのSHA256をバージョン文字列のみ正規化して保持し、組み立て後との完全一致を検証する。
パック・画像は変更しない。ソースとbundleの不一致、未登録断片、構文エラーは検査で失敗させる。
起動/カード/雇用/Bot/追加パック/時計/模擬同期に加え、TESTの接続禁止・保存先分離も検証する。
全カード全組み合わせの実機確認、Safari描画・タッチ、実Supabaseの複数端末対戦は別途必要であり、模擬検査で確認済みとはしない。

本番向けPRはマージしない。テスト実施のため本番へ反映することもしない。
